02

客户端：先确认设备，再决定装哪一个

客户端不是一个软件，而是一类工具。按设备类型分，通常落在桌面、移动与路由器三种情况里。

桌面端

Windows 与 macOS

桌面端常见的做法是使用支持订阅导入的客户端：安装后把订阅地址粘贴到「订阅」或「配置」入口，保存并刷新节点列表即可。桌面端配置项较多，适合需要分流规则或需要排查问题的人。系统版本过旧时，部分客户端可能无法正常运行，安装前先看一下软件自身给出的系统要求。

移动端

Android 与 iOS

两类系统的处理方式并不一样。Android 通常可以直接安装客户端并导入订阅；iOS 的可用性受应用商店区域影响，不同地区上架情况不一致。因此本页不指定具体应用名称，也不提供下载地址。无论哪一种系统，导入前都应确认订阅地址没有被公开传播。

路由器与软路由

网络层统一配置

把配置放在路由器上，可以让同一网络下的设备共用一份连接，省去逐台设置的麻烦。这种方式对动手能力要求更高，升级与排错也更依赖设备本身，并且需要注意设备数如何计算。参考套餐没有对路由器场景单独说明，部署前建议先确认固件与客户端是否匹配。

本页不提供任何客户端的安装包或下载地址。请只从你信任的来源获取软件，并在导入前确认订阅地址处于私密状态；不要把订阅链接发到公开群组、论坛或截图里。

03

使用说明：六个步骤，从导入到排查

按顺序执行即可。每一步都给出判断依据，避免在不确定的情况下反复更换设置。

  1. 确认账号与服务状态

    开始配置前，先确认订阅处于有效期之内，并核对同时在线设备数是否已经接近上限。超出上限时，常见的表现是已有设备频繁掉线，而不是完全无法连接。

  2. 复制订阅地址

    订阅地址相当于一份配置文件，包含节点与规则信息。复制时注意不要带入多余空格或换行；同时不要把它发到公开渠道，一旦外泄，建议及时更换。

  3. 选择客户端并导入

    打开与你设备匹配的客户端，找到「订阅」「配置」或「Profile」入口，粘贴地址后保存，等待列表拉取完成。部分客户端需要手动点一次刷新才会显示节点。

  4. 选择节点并连接

    初次使用可以先选择延迟较低的节点，连接后打开一个常用网站确认是否生效。如果页面打不开，先换一个节点测试，以区分是节点问题还是本地设置问题。

  5. 检查流量是否真的走了代理

    网页能打开但速度异常时，先看客户端的系统代理或分流规则是否开启，再检查本地安全软件是否拦截了连接。桌面端尤其容易出现「客户端已连接、系统代理未开启」的情况。

  6. 按固定顺序排查故障

    建议顺序：订阅是否过期 → 客户端版本是否过旧 → 节点是否可用 → 本地网络是否正常 → 设备数是否超限。多数问题能在这五步之内定位，不必急于重装系统或更换设备。

常见问题：按编号查，答案写在问题下面

这些问题覆盖身份、价格、设备数、流量规则与客户端四个方向，回答尽量明确，也标出页面无法代为确认的部分。

  1. 本页是 SaySS 的官方网站吗？

    不是。本页是围绕 SaySS 关键词整理的信息页，用于汇总套餐结构、客户端分类与使用步骤。页面没有获得品牌方授权，也不代表任何官方渠道，不提供注册、付款或下载入口。

  2. 页面上的价格可以直接付款吗？

    不能。价格是参考信息，用于比较三档套餐之间的差异。实际价格、计费周期与优惠方式以提供方的正式页面为准。本页不处理订单，也不代收费用。

  3. 一个账号可以同时在几台设备上使用？

    参考套餐中，基础版标注 3 台、旗舰版 5 台、团队版 20 台同时在线。这个数字通常指同一时间的在线设备数，而不是累计可登录的设备数。具体口径以提供方说明为准。

  4. 流量用完了会怎样？

    常见处理方式有两种：当月停止服务，或降速后继续可用。具体规则取决于提供方的策略，本页无法代为确认。建议在开通前直接查看对应档位的流量说明与超量处理方式。

  5. 导入订阅后看不到节点怎么办？

    先确认订阅地址完整、没有多余空格；再检查设备时间是否准确；然后尝试手动刷新订阅。如果列表仍然为空，可能是订阅已过期或地址已经更换，需要回到获取订阅的来源核对。

  6. iOS 上应该用哪个客户端？

    iOS 客户端的可用性受应用商店区域影响，不同地区的上架情况并不一致，因此本页不指定具体应用名称，也不提供下载链接。建议以提供方给出的客户端说明为准，并注意不要使用来源不明的安装方式。

  7. 可以在路由器上使用吗？

    参考套餐没有对路由器场景单独说明。是否可行取决于客户端能否在你使用的路由器固件上运行，以及设备数如何计算。部署前建议先确认这两点，再决定是否把配置放到网络层。

  8. 遇到问题应该怎么反馈？

    本页不提供客服入口。如果你已经在使用某个服务渠道，优先通过该渠道的工单或支持方式反馈，并附上客户端类型、系统版本、出错步骤与提示文字。信息越完整，排查越快。
